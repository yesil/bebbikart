# BebbiKart — Shared Contracts

**Owner:** WS1 (Foundations). **Changes:** by pull request, reviewed by at least one person from each affected workstream.
**Implementation:** for the Bun side (server, phone site, pipeline), everything here becomes code in `packages/shared`, written in **plain JavaScript** with [zod](https://zod.dev) schemas as the runtime definition of each shape (JSDoc comments for editor hints). The shapes below use TypeScript-style notation **for readability only**; there is no TypeScript in the codebase. The **Godot game** can't import JS, so `bun run kit:export` generates `res://net/protocol.gd` (enums, message names, default config), `res://data/racer_kit.json` and `res://data/pkg_default/spec.json` from `packages/shared`. That's why this doc is the source of truth and not the code. If this doc and the code ever disagree, fix whichever is wrong in the same PR.

Read [`README.md`](README.md) §2 first for the game rules these contracts encode.

---

## 1. Conventions

- **IDs** are prefixed random strings: `ply_…` player, `dev_…` device, `job_…` asset job, `pkg_…` asset package, `bld_…` build, `run_…` run, `ses_…` session. Generated by the server (use `nanoid`, 12 chars after the prefix).
- **Times:** wall-clock timestamps are ISO-8601 strings in UTC. **Durations** are integer milliseconds (`…Ms`). Run times are **simulation** milliseconds (ticks × 1000/60).
- **JSON field names** use camelCase. **Enum values** use lower_snake or single lowercase words, as listed.
- **Validation:** parse REST bodies and WS messages with their zod schemas (it's free type safety). Invalid input → `400` or a WS `error` message. No further hardening.
- **Versioning:** every WS message carries `v: 1`. Bump only for breaking changes.

## 2a. Tracks and laps

The game manager picks the session's **track** in config (`track`) from the options menu on the big screen (`game.config.set`, §7). Both tracks have the same four sections and the same three forks, so builds, splits and coach tips mean the same on either.

- `countryside` is point to point: a run is one trip from start to finish, and `elapsedMs` ranks.
- `village` is a **loop** (in `LOOP_TRACKS`): the racer crosses the line and keeps going. Each crossing books a lap (`game.run.lap`). The run finishes after `lapsPerRun` laps, or at the next crossing after the player taps **Pit in** (`phone.stop` → `run.stop`). The player's **best lap** ranks: `Player.bestTimeMs` and `LeaderboardEntry.bestTimeMs` hold the best lap, `run.splits` and the ghost trace are the best lap's, and `runTimeCapMs` applies per lap. A run that fails after completing laps still reports them (`laps`, `bestLapMs`), and those laps count.
- `track` can't change while a session is running (the leaderboard is per session). `PATCH /api/admin/config` with a new track during a session → 409 `track_locked`. The game loads the matching world on `config.updated`, and refuses (logs an error and shows it on the big screen) a track it doesn't have.

## 2b. Language

The game manager picks the **language** (`language`: `"en"` English or `"de"` German, Swiss-friendly: "ss", never "ß") in the options menu on the big screen. The game keeps the pick in its own settings, applies it to every big-screen string right away, and sends `game.config.set { language }` (also right after each `welcome`, when the server's config says otherwise). The server answers with `config.updated`, so every phone switches live; phones never set it.

- Every user-facing string lives in one string table per app with the same keys in `en` and `de`: `apps/web/src/copy.js` (phone), `apps/game/data/strings.json` (big screen), `COACH_COPY` in `packages/shared/src/coach.js` (coach tips, written by the server in `config.language`). `bun test` checks the key sets match.
- **No fallback language:** a missing key or an unknown language throws (JS) or `push_error`s and shows the missing key on screen (Godot). It never quietly shows English.
- Racer titles, taglines and personality words come from the racer designer and stay in the language it wrote them in.

## 2c. Race start (countdown)

Kids in a group press Go a few seconds apart; the countdown makes them race each other. When a run
reaches the game and no countdown is open, the game opens one of `startCountdownMs`: the big screen
shows the lights (3, 2, 1, GO) and the racers lined up, and every run that arrives before the lights
go green joins it. The game sends `game.run.grid { runId, goInMs }` for each run as it joins; the
server relays it to that racer's phone as `run.grid`, which counts down too. At green the group
leaves together (`game.run.started` each): side by side in the four start slots, a second row as
soon as the first has pulled away. A run that arrives after green opens the next countdown. With
`startCountdownMs: 0` there is no countdown and no `game.run.grid`. Run times start when the racer
leaves, so waiting on the grid never costs time.

Every phone also hears `grid.updated { goInMs, racers: [{ playerId, nickname }] }` each time a run
joins the open countdown, so friends still in the garage or on the result screen see "Mia is on the
grid! Join the race: 2" and can press Go to join that start.

## 2d. Stretches ("see why")

Every track is cut into **stretches** (`TRACK_STRETCHES[track]` in `enums.js`, in driving order), finer
than the four sections: each tests one ability (a sign at its start says which), each fork piece is a
stretch of its own (the safe alternative tests none; `slick` marks a wooden deck that loses grip in the
rain), and connectors belong to a neighbour. Village: `main_street` (grip), `kicker` (jump) or
`churchyard`, `church_hill` (grip), `ford` (water) or `covered_bridge` (slick), `farm` (grip, muddy),
`cobbles` (bounce), `ridge` (stability), `alpbach` (water), `causeway` (stability) or `arcades`,
`square` (grip). Countryside: `bumpy_road` (bounce), `kicker` (jump) or `knoll_road`, `hilltop` (speed),
`ford` (water) or `stone_bridge`, `causeway` (stability) or `hedge_lane`, `rainbow_bends` (grip).

The sim tags every course segment with its stretch (a segment without one, or with another track's,
is a broken course: the game refuses to race it). Each lap it records the time on each stretch
(`StretchTime { id, ms, lostMs }`, in driving order; they add up to the lap within a tick) and the time
the loss events on it cost (`lostMs`); every `RunEvent` names its `stretch`. `game.run.lap` carries the
lap's stretches; `game.run.finished` the best lap's (point to point: the run's); `game.run.failed` the
stretches done on the lap it failed in, plus `stretch` where it ended.

The server keeps them on the run (`stretches`, and `lapStretches` for every completed lap on a loop)
and sends the phone, in `run.ended`, each of the run's stretches as a `StretchResult`: this run's
time, the player's own best on that stretch in earlier runs this session (`bestMs`), and the
session's fastest on it, whoever did it (`fastestMs`, `fastestPlayerId`, `fastestNickname`; this run
included). Bests come from every completed lap (a point-to-point run: finished runs) on the session's
track since the session started. The coach (§8) picks its tip from them.

## 2e. Track maps (phone)

The phone draws each track from `TRACK_MAPS` (`packages/shared/src/track-maps.js`, `trackMap(track)`
throws for a track without one): the sim course flattened to 2D polylines, one per segment in course
order, each with its `stretch` (§2d), `fork` and `choice`, points about 2.5 m apart; `bounds`, the
`start` line and `loop`. Map coordinates are metres, x = world x, y = −world z (north up). The JSON is
generated from the Godot sim (`bun run maps:export`, `tools/export_track_maps.gd`); `bun run
maps:check` and `village_laps.gd` fail when a map no longer matches its course, and a bun test checks
each map's stretches against `TRACK_STRETCHES`. Never edit the JSON by hand.

## 2f. Setups ("peek at a faster racer")

Kids learn by looking at what works. A **Setup** is what a time was set with: the build raced
(`stars`, and the `routes` those stars chose, §2h) and the `weather` on that lap (`WeatherKind[]`: rain or wind active at
any time on the lap; `game.run.lap` carries each lap's `weatherSeen`, the server keeps them as
`Run.lapWeather`; a point-to-point run uses the run's `weatherSeen`, and loop runs recorded before
laps carried weather use the run's). `LeaderboardEntry.setup` is the setup of the player's best
(the best lap's). In `run.ended`, each `StretchResult` with a session fastest carries
`fastestSetup`, and a fork piece also carries `other`: the session's fastest through the same fork
the other way (`{ id, ms, playerId, nickname, setup }`), so the phone can say "Mia takes the ford".
The phone shows setups; it never copies one into the player's build.

## 2g. Driving: Push and Boost

The autopilot steers, picks the line and brakes. Kids drive it with two controls on the phone:

- **Push** (hold the big button): `phone.push { runId, on: true }` when the thumb goes down,
  `{ runId, on: false }` when it comes up; the server relays each as `run.push { runId, on }`.
  While pushed the kart has a little more top speed (`PUSH_TOP_SPEED` in `sim/tuning.gd`), brakes
  late and corners as if the road were dry and grippy, so it slides wide in a tight or wet bend
  (`slip` events, time lost) and can leave the road on the worst ones. Letting go hands the
  speed back to the autopilot. The skill is knowing where it is safe to push. The server sends
  `run.push { on: false }` itself when the racer's phone disconnects mid-hold, and the game
  drops a push when the run ends; a push for a run that is not racing (on the grid) is kept
  and applies from the start.
- **Boost** (tap, `boostsPerRun` a run) as before (README §2 rule 6).

There is no driving style any more: the autopilot always drives as the old "balanced", and Push
is daring, live, when the kid wants it.

## 2h. Routes from stars

Kids no longer pick a route at the three forks: their stars choose. `ROUTE_STARS` in `enums.js`
sets, per fork, the ability and how many of its stars take the risky way:

```ts
const ROUTE_STARS = {
  ramp: { ability: "jump", stars: 8, choice: "jump" }, // else "around"
  pond: { ability: "water", stars: 6, choice: "water" }, // else "bridge"
  crossing: { ability: "stability", stars: 4, choice: "exposed" }, // else "sheltered"
};
```

`routesFor(stars)` in `build.js` applies it. The thresholds are where the sweep
(`tools/sweep.gd`, the fork tables) finds the risky way faster than the safe one in calm weather
on both tracks; re-run it after any tuning change. The phone body for a build is `{ stars }`; the
server stores `routes: routesFor(stars)` on the `Build`, so the game, setups (§2f) and the coach
read `build.routes` as before. The garage says which way the stars take ("6 water stars: you
splash through the ford", "2 more jump stars and you take the kicker").

## 2i. Duel mode (king of the hill)

`config.mode` is `"race"` (free races: everything above, unchanged) or `"duel"`. The game manager
picks it in the big screen's options menu like the track (`game.config.set { mode }`); it can't
change while a session is running (`mode_locked`). In a duel the session's fastest racer is the
**champion** and rests while their time stands; everyone else takes turns in a **line** to beat
it, one lap each, against the clock.

- **The champion** is rank 1 on the leaderboard (best time; on a loop, best lap; ties to the
  first, rule 12). Nobody holds the title until the first finished lap of the session.
- **The line.** In duel mode Go (`phone.go`, `POST …/runs`) joins the line instead of launching:
  `queue.updated` shows the player at the back. `phone.queue.leave {}` (and Quit) leaves it. A
  player can't join twice (`in_line`), nor while racing (`run_in_progress`). After a lap the
  racer is out of the line and presses Go again to rejoin; nobody is put back automatically.
  Stars can change at any time; a run uses the build saved when it is launched.
- **The champion rests.** The champion may join, but always waits behind everyone else: they are
  launched only when nobody else is waiting, and anyone who joins later goes ahead of them. A
  dethroned champion is an ordinary racer again.
- **Two halves.** The big screen has a `left` and a `right` half, each running one racer at a
  time. As soon as a half is free the server launches the first in line there (no press needed):
  `run.start` carries `side`, `Run.side` keeps it, and the phone says "You're on the left, in
  red" (left red, right blue). Both halves free: left first. When a run ends its half shows the
  result for `duelResultMs`, then takes the next in line. The halves start at different times.
- **One lap.** Duel runs race one lap on a loop track (`lapsPerRun: 1` on `run.start`); the point
  to point track is one trip anyway. Pit in is hidden.
- **Against the clock, not each other.** Collisions are off in a duel: the two karts pass through
  each other (no `bumped` events). Each run gets its own start lights in its half (§2c: a duel run
  never joins another run's countdown; `run.grid` still counts it down on the phone). Weather
  stays shared and random.
- **Judging.** A lap is judged against the record as it stands when the lap ends: faster than the
  champion's time takes the title (`run.ended.duel.newChampion`); a failed lap has no time. The
  phone shows "New champion!" or "0.8 s short of Mia" (`duel.gapMs`, `duel.recordNickname`).
- **Offline phones.** A player whose phone is offline when their turn comes is taken out of the
  line and listed in `queue.updated.skipped` until they join again (the phone shows "Your phone
  was offline at your turn"). Facilitator-managed racers (no device) are never skipped.
- **Waiting game.** The server launches only while the session is running, the game is online and
  on the right track; otherwise the line holds. At session end the line closes (`queue.updated`
  empty), runs on track finish, and the podium shows as usual.
- **Screen layout.** `queue.updated.split` is true when the session has 2 or more racers (status
  ready); the game then splits the screen vertically, an idle half showing who is next. With one
  racer the game gives that racer the full screen. The picture-in-picture, the camera director's
  cuts, "Show me on the big screen" and the "Join the race!" grid call are off in duel mode.

```ts
interface QueueState {
  // queue.updated, to phones, admin and game: right after welcome and on every change
  line: { playerId: string; nickname: string }[]; // waiting, in launch order (the champion last)
  racing: { side: Side; playerId: string; nickname: string; runId: string }[]; // on track or on the grid
  champion?: { playerId: string; nickname: string; timeMs: number; tries: number }; // tries: duel laps by others since the record was set
  split: boolean; // 2+ racers in the session
  skipped: string[]; // playerIds taken out of the line because their phone was offline at their turn
}
type Side = "left" | "right";
```

### Ghost trace

The game samples each run at **10 Hz**. A trace is stored only for a player's **best** finished run.

```ts
interface GhostTrace {
  runId: string;
  hz: 10;
  // Flat array, 5 numbers per sample: x, y, z, yawRad, pitchRad. Rounded to 2 decimals.
  samples: number[];
}
```

About 40 s × 10 Hz × 5 ≈ 2,000 numbers, small enough to send over WS.

## 5. Asset package format

A racer is **data, not pictures**: a `RacerSpec` written by DeepSeek (WS5), stored by the server (WS2), built in 3D by the game (WS3). The game also renders a few PNGs of each racer for the phone.

```
data/assets/pkg_xxx/
  spec.json                    # RacerSpec
  drawing_character.jpg        # downscaled crops of the originals ("drawn by me", optional sticker)
  drawing_vehicle.jpg
  hero.png                     # rendered by the game: full racer, 3/4 view, transparent, 1024 px
  avatar_happy.png avatar_excited.png avatar_sad.png   # rendered by the game, 512 px square
```

```ts

    hat?: { type: string; color: PaletteRef };
    arms: { color: PaletteRef };
    outfit?: { type: string; color: PaletteRef; pattern?: Pattern }[]; // ≤ 2: tshirt | jacket | dress | skirt | ruffle_skirt | shorts | overalls

    extras: Extra[]; // ≤ 10
  };

    color: PaletteRef;
    accent: PaletteRef;

}
interface Extra {
  shape: string; // kit extraShapes: sphere capsule box cone cylinder torus star heart lightning flame moon flower leaf cloud diamond drop bowtie glasses cape
  socket: string; // from kit catalog, e.g. "head_top", "body_front", "ride_back"
  offset: Vec3;
  scale: Vec3;
  rotationDeg: Vec3; // clamped to small ranges per socket
  // cone, capsule and cylinder stand on their base at the socket and grow along their local +y
  color: PaletteRef;
  mirror?: boolean; // also place a copy on the other side (ears, horns)
}

interface AssetManifest {
  packageId: string;
  playerId: string;
  updatedAt: string;
  spec: RacerSpec;
  drawings: { character: string; vehicle: string };
  renders: { hero?: string; avatar_happy?: string; avatar_excited?: string; avatar_sad?: string };
  fallback?: boolean; // DeepSeek failed → default spec in the kid's colours
}
```

Part names (`body.shape`, `face.eyes`, `hat.type`, sockets…) come from the **kit catalog** in `packages/shared/src/racer-kit.js`, which WS3 keeps in sync with the parts it builds in Godot.

**Default racer** `pkg_default` (a default spec) ships with the game, for anyone without a valid spec yet.

## 7. WebSocket protocol

One endpoint, `GET /ws`. The first message must be `hello`. The server replies `welcome` or closes with code 4001.

```ts
interface Envelope<T extends string, P> {
  v: 1;
  type: T;
  id: string;
  ts: string;
  payload: P;
}
```

### Roles

| Role    | `hello` payload                                    | Who                                                                |
| ------- | -------------------------------------------------- | ------------------------------------------------------------------ |
| `phone` | `{ role: "phone" }` (cookie identifies the device) | Phone app                                                          |
| `game`  | `{ role: "game", gameKey, track? }` (`BK_GAME_KEY` env) | Big-screen game. **Exactly one**; a second one replaces the first. `track` = the course it has loaded: while it differs from `config.track` (the game reloads the new world once its track is empty), Go is refused with `track_changing`. |
| `admin` | `{ role: "admin", pin }`                           | Facilitator console                                                |

### Phone → Server

| type          | payload                     |
| ------------- | --------------------------- |
| `phone.go`    | `{}`, same as `POST …/runs` |
| `phone.boost` | `{ runId }`                 |
| `phone.stop`  | `{ runId }`, loop tracks: "Pit in", finish at the next line crossing |
| `phone.watch` | `{ runId }`, "Show me on the big screen": the camera cuts to this racer soon (see Camera below) |
| `phone.push`  | `{ runId, on }`, Push held down (`on: true`) or let go (§2g) |
| `phone.queue.leave` | `{}`, duel mode: leave the line (§2i) |

### Server → Phone

| type                         | payload                                                                                        | When                                                  |
| ---------------------------- | ---------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| `welcome`                    | `{ session, config, me?: PlayerView, weather }`                                                | On connect                                            |
| `player.updated`             | `PlayerView`                                                                                   | Any change to this player (job progress, build, best) |
| `player.removed`             | `{ playerId }`                                                                                 | The player quit or the admin removed them: back to the join screen |
| `run.queued` / `run.started` | `{ run }`                                                                                      |                                                       |
| `run.grid`                   | `{ runId, goInMs }`                                                                            | On the start grid: the lights go green in goInMs (§2c) |
| `run.heat`                   | `{ heatId, done, entries: HeatEntry[] }`                                                       | A heat-mate's run ended (see "Heats" below)           |
| `grid.updated`               | `{ goInMs, racers: [{ playerId, nickname }] }`                                                 | To every phone: a run joined the open countdown (§2c) |
| `paddock.updated`            | `PaddockEntry[]`                                                                               | Everyone in the session (see "Paddock" below)         |
| `run.progress`               | `{ runId, progress: 0..1, elapsedMs, section: SectionId, deltaVsBestMs?: number, boostsLeft, lap?, lapMs?, place?, of? }` | ≤ 5 Hz; on a loop `progress` is of the current lap, `lap` counts from 1; `place` of `of` = position right now in its heat (racers home first, then by distance) |
| `run.lap`                    | `{ runId, lap, lapMs, isLapBest, deltaVsBestLapMs? }`                                          | Loop tracks: each line crossing; `isLapBest` = the player's fastest lap this session |
| `run.section`                | `{ runId, section, splitMs, bestSplitMs? }`                                                    | Each section line crossed                             |
| `run.ended`                  | `{ run, isPersonalBest, rank?, coach: CoachTip, stretches: StretchResult[], duel? }`           | Finish or fail (stretches §2d; empty when aborted). Duel runs: `duel: { newChampion, gapMs?, recordNickname? }`, `gapMs` = this lap minus the record it was judged against (positive = slower; absent without a time or a record) |
| `queue.updated`              | `QueueState`                                                                                   | Duel mode (§2i): right after welcome and on every change of the line, the halves or the champion |
| `leaderboard.updated`        | `LeaderboardEntry[]` (top 20)                                                                  |                                                       |
| `session.updated`            | `Session`                                                                                      |                                                       |
| `weather.updated`            | `WeatherState`                                                                                 | Every phase change (incl. `warning`)                  |
| `config.updated`             | config                                                                                         |                                                       |
| `camera.updated`             | `{ playerId?, runId? }`: the racer the big-screen camera follows now; empty when nobody         | Every camera cut (relayed `game.camera`)              |
| `error`                      | `{ code, message, refId? }`                                                                    |                                                       |

### Paddock

Every phone gets `paddock.updated` (everyone in the session) right after `welcome` and whenever
someone joins, leaves, goes on or off line, moves to the next design step, gets their avatar, or
starts or ends a run, so a kid waiting for their racer sees their friends' racers being made.

```ts
interface PaddockEntry {
  playerId: string;
  nickname: string;
  status: PlayerStatus;
  stage?: "looking" | "designing" | "critiquing" | "refining"; // status processing
  avatarUrl?: string;
  connected: boolean;
  racing: boolean; // on the track or on the start grid
}
```

### Heats

Runs that left from the same start countdown (§2c; however many rows it took to release them),
or, without a countdown, within 2.5 s of each other, are a **heat**: they raced each other. Each time one of them ends, the
server sends every phone in the heat `run.heat`, so a kid who is home first watches the others
come in; `done` is true once the last one is home. `heatId` is the heat's first run id. A heat of
one sends nothing.

```ts
interface HeatEntry {
  playerId: string;
  nickname: string;
  avatarUrl?: string;
  place?: number; // by time among the heat's racers with a time (finish time, or best lap on a loop)
  timeMs?: number;
  outcome?: RunOutcome; // absent: still racing
  failReason?: FailReason;
}
// entries: placed racers by place, then those still racing, then the ones out without a time.
```

### Game → Server

| type                | payload                                                                                      |
| ------------------- | -------------------------------------------------------------------------------------------- |
| `game.run.started`  | `{ runId }` (racer crossed the start line)                                                   |
| `game.run.grid`     | `{ runId, goInMs }`: the run joined the start countdown (§2c); relayed to its phone as `run.grid` |
| `game.run.progress` | `{ runId, progress, elapsedMs, section, boostsLeft, lap?, lapMs? }`, ≤ 5 Hz (lap fields on loops) |
| `game.run.section`  | `{ runId, section, splitMs }`                                                                |
| `game.run.lap`      | `{ runId, lap, lapMs, elapsedMs, splits, stretches, weatherSeen, isBest }`: loop tracks, each line crossing (`isBest` within this run; `stretches` this lap's, §2d) |
| `game.run.finished` | `{ runId, elapsedMs, splits, stretches, events, boostsUsed, weatherSeen, trace: GhostTrace, laps?, bestLapMs? }` |
| `game.run.failed`   | `{ runId, reason: FailReason, section, stretch, elapsedMs, splits, stretches, events, boostsUsed, weatherSeen, laps?, bestLapMs? }` |
| `game.weather`      | `WeatherState` (on every phase change)                                                       |
| `game.capacity`     | `{ freeSlots }` (if the game ever wants fewer than `maxConcurrentRuns`)                      |
| `game.config.set`   | `{ track?, lapsPerRun?, sessionMinutes?, language?, mode? }`: game manager options (see below) |
| `game.session.end`  | `{}`: ends the running session                                                                |
| `game.session.start`| `{}`: starts a session (`sessionMinutes`); after an ended one, a **new** session with an empty leaderboard |
| `game.camera`       | `{ runId? }`: the run the big-screen camera follows now (every cut; no `runId` when the course is empty) |

**Game options live on the big screen.** Phones are players: they join, race and quit (Pit in), and never set options. The game manager sets the track, laps, session length and language in the game's options menu, which sends the `game.config.*` / `game.session.*` messages above. The server answers with `config.updated` / `session.updated` to every client, or with `error { code, message, refId }` where `refId` is the refused message's `id` (`track_locked` when the track changes during a running session, `mode_locked` likewise for the mode, `bad_request` when starting a running session, `bad_message` for any other field). Switching track = `game.session.end`, `game.config.set { track }`, `game.session.start`, sent back to back. Racers stay; bests and ghosts don't carry over to the new session. The admin REST routes do the same for scripts.

The **game is the authority** for timing and outcomes. The server trusts these messages and records them.

**Camera.** The big screen's camera director takes turns between the racers on the course (every 8 s by default, set in the game's options menu). A phone's `phone.watch` reaches the game as `run.watch` for the player's current run (ignored without one; a run parked on the start grid during the countdown counts); the game queues that racer for one of the next cuts, at most one cut every 3 s, so taps from several phones can't make the camera flicker. On every cut the game sends `game.camera`, and the server tells every phone with `camera.updated` (`playerId` added from the run), so the racer on camera can show "You're on the big screen!".

## 8. Coach tips (`packages/shared/src/coach.js`)

A **pure JS function** run by the server, which sends the result to the phone in `run.ended`. WS3 designs the rules (they encode gameplay knowledge):

```ts
interface CoachTip {
  key: string;
  text: string;
  stretch?: StretchId; // the stretch it is about (the phone highlights it, §2d)
  ability?: Ability;
  route?: { fork: ForkId; choice: string };
}
function coachTip(run: Run, build: Build, best: Run | undefined, language: Language, stretches: StretchResult[]): CoachTip; // throws on an unknown language or track, or a finished run without stretches
function abortTip(language: Language): CoachTip; // key "aborted", for runs that were stopped
```

Rules, in priority order:
1. Failed → a tip about the fail, naming the **stretch where it ended** (`failStretch`), from the reason and that stretch's dominant event. E.g. `off_track` on `farm` with `slip` events → "Slipped on the muddy farm track! Try +2 grip or Careful style."
2. Finished slower than your best → the **stretch with the biggest loss against your best on it** (≥ 300 ms; on your first run: against the session's fastest racer on it, if that is someone else). Its tip: an off-zone boost, bumps or a missed exit there keep their own tip; else the stretch's star ("Lost 1.3 s on the muddy farm track. Try +2 grip!"), or on a fork's safe alternative the other route ("Try the ford next time!"; on the covered bridge in the rain, "Lost 1.5 s on the wet, slippery bridge. Try the ford!"). Within a hair of your best everywhere → "So close to your best! Go again?".
3. Finished, first time (nobody faster) / new best → a cheer plus one experiment to try ("New best! Brave enough to try the water shortcut?").

Stretch names are per track and language (`STRETCH_NAMES`, with their preposition; `ROUTE_NAMES` for the other route).

Text is short (≤ 70 chars), positive and kid-readable, in `config.language` (§2b). The full copy table, one per language, lives in `coach.js` so it is reviewed in one place.
